# Unified benchmark (2026-10-20)

`bench_unified.py` — 统一口径 harness：row vs chunk-batch vs pure-SQL，threads=1/4，1M 行，warmup+min-of-5。
设计规则继承 `run.py`（列参数防常量折叠）；batch 臂用**注册名调用**（`luajit_vi('bx2', v)`），这是唯一走 chunk-batch 路径的形态——匿名 source（`luajit_vi('return x*2', v)`）按源码注释走 scalar-per-row 语义，与 row 版同速（实测 34.5 vs 33.8 ms）。

## 结果（WSL, DuckDB v1.5.6, luajit v0.32.5 build）

| 配置 | t=1 | t=4 |
|---|---|---|
| row-mode `luajit_i` (anon) | 34.7 ms | 11.6 ms |
| batch `luajit_vi` (registered) | **17.8 ms** | **4.9 ms** |
| pure SQL `v*2` | 1.1 ms | 0.6 ms |

- batch vs row（t=1）= **1.95×**（注册表 description.yml 主张 ~1.9× ✅ 复现）
- batch 4 线程 vs row+serial = 7.1×；batch 并行扩展 3.6×
- pure SQL 参照：UDF 路径慢 ~16×——论文呈现时须带此参照并讨论适用场景（SQL 表达不了的逻辑才值得走 UDF）

## 论文写作注意

1. 数字引用统一取本表（同机同 run 同负载），注册表旧数字（13ms/18ms）系不同机器/负载，勿混用。
2. 「匿名=per-row、注册名=chunk-batch」的调用形态差异是 §2.2 的设计点，也是 README 该显式写的坑。
3. 复现：`python3 benchmark/bench_unified.py`（需 `configure/venv` + `build/release/luajit.duckdb_extension`）。
